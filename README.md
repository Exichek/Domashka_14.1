# E-commerce

Учебный проект интернет-магазина на Python. Разработка продолжается в рамках домашних заданий **14.1, 14.2, 15.1, 16.1, 16.2 и 17.1** в одном репозитории.

Проект демонстрирует объектно-ориентированное программирование, инкапсуляцию, наследование, магические методы, абстрактные классы, миксины и обработку исключений.

## Возможности

### Product — товар

Поля товара:
- `name` — название;
- `description` — описание;
- `__price` — приватная цена;
- `quantity` — количество на складе.

Основные методы:
- `price` — свойство для чтения и изменения цены; нулевое или отрицательное новое значение отклоняется;
- `new_product()` — создание товара из словаря;
- `__str__()` — строковое представление товара;
- `__add__()` — общая стоимость складских остатков двух товаров **одного класса**.

**Изменение в 17.1:** создание `Product` с количеством `0` прерывается исключением `ValueError` с точным сообщением:

```text
Товар с нулевым количеством не может быть добавлен
```

Проверка действует и для наследников `Smartphone` и `LawnGrass`, поскольку они вызывают конструктор `Product`.

### BaseProduct и CreationLogMixin

`BaseProduct` — абстрактный базовый класс (`ABC`) с обязательными методами `__str__()` и `__add__()`.

`CreationLogMixin` выводит имя класса и аргументы конструктора при создании товара. Для построения представления используются `__repr__()` и `inspect.signature()`.

Пример вывода:

```text
Product('Телефон', 'Описание', 1000.0, 5)
```

`Product` наследуется одновременно от `CreationLogMixin` и `BaseProduct`.

### Smartphone и LawnGrass

Оба класса напрямую наследуются от `Product`.

Дополнительные поля `Smartphone`:
- `efficiency` — производительность;
- `model` — модель;
- `memory` — память;
- `color` — цвет.

Дополнительные поля `LawnGrass`:
- `country` — страна производства;
- `germination_period` — срок прорастания;
- `color` — цвет.

### Category — категория товаров

Класс наследуется от `BaseCatalogEntity`. Содержит название, описание и приватный список товаров `__products`. Счётчики `category_count` и `product_count` учитывают созданные категории и добавленные в них товары.

Методы и свойства:
- `add_product()` — добавляет объекты `Product` и его наследников, отклоняя объекты неподходящих типов;
- `products` — возвращает строковое представление списка товаров;
- `__str__()` — название категории и суммарное количество единиц на складе;
- **`average_price()`** — средняя цена товарных позиций;
- `middle_price()` — альтернативное имя метода средней цены для совместимости с демонстрационным сценарием.

Средняя цена рассчитывается по формуле:

```text
Сумма цен всех товаров / Количество товарных позиций
```

Количество единиц каждого товара на складе **не влияет** на среднее арифметическое. Для пустой категории возвращается `0.0`; деление на ноль обрабатывается через `try` / `except ZeroDivisionError`.

### Order — заказ (дополнительное задание 16.2)

Класс наследуется от `BaseCatalogEntity` и хранит:
- `product` — приобретаемый товар;
- `quantity` — количество в заказе;
- `total_price` — стоимость (`product.price * quantity`).

Допускается один товар на заказ. Проверяются тип товара и количество. При создании заказа остаток товара на складе не уменьшается.

### BaseCatalogEntity

Общий абстрактный родитель `Category` и `Order`. Хранит `name` и `description`, требует реализации `__str__()`.

### Обработка исключений (17.1)

Добавлен собственный класс `ZeroQuantityError`, наследующий `ValueError`, с сообщением:

```text
Товар с нулевым количеством не может быть добавлен
```

Он используется при добавлении товара с нулевым количеством в категорию и при оформлении заказа с нулевым количеством товара.

Для операций добавления применяются `try`, `except`, `else`, `finally`:
- при успешном добавлении выводится `Товар успешно добавлен`;
- при нулевом количестве выводится текст исключения, после чего ошибка передаётся вызывающему коду;
- в любом случае выводится `Обработка добавления товара завершена`.

При неудачном создании категории счётчики корректируются, чтобы не учитывать частично добавленные товары.

## Установка и запуск

Необходимы Python 3.14 и Poetry.

```bash
poetry install
poetry run python main.py
```

`main.py` — демонстрационный сценарий домашнего задания **17.1**, предоставленный преподавателем (с минимальными техническими исправлениями при необходимости).

## Тестирование

Тесты проверяют функциональность заданий 14.1–17.1, включая:
- инициализацию товаров, категорий и заказов;
- инкапсуляцию, наследование и магические методы;
- абстрактные классы и логирование миксина;
- запрет товаров с нулевым количеством;
- средний ценник обычной и пустой категории;
- собственное исключение `ZeroQuantityError`;
- успешные и неуспешные операции добавления и работу `finally`;
- сохранение поведения предыдущих заданий.

Запуск тестов и создание HTML-отчёта:

```bash
poetry run pytest --cov=src --cov-report=html --cov-report=term-missing
```

Отчёт сохраняется в `htmlcov/index.html` и включается в репозиторий.

**Результат задания 17.1:** 67 пройденных тестов, покрытие функционального кода — **100% (126 из 126 инструкций)**.

## Проверка качества кода

```bash
poetry run flake8 src tests
poetry run isort --check-only src tests
poetry run black --check src tests
poetry run mypy src main.py
```

Настройки: Flake8 — до 120 символов в строке, Black — стандартное форматирование (88 символов), Isort — профиль `black`.

Преподавательский `main.py` используется прежде всего для проверки запуска. Он не обязан соответствовать всем стилистическим правилам, применяемым к собственным исходникам и тестам.
